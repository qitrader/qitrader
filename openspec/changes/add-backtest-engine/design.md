## Context

qitrader 是一个基于事件驱动架构的加密货币交易系统。当前仅支持实盘交易，策略通过 `Strategy` 基类接收实时行情事件（Tick/Book）并发送交易指令。回测功能需要在不修改策略代码的前提下，用历史数据替代实时行情，用模拟撮合替代真实交易所。

### 关键约束
- 单线程 + Boost.Asio 协程架构，回测引擎必须适配此模型
- 策略代码（`Strategy` 基类接口）在实盘和回测间完全复用，零修改
- 数据格式兼容现有 `TickData`、`BarData`、`BookData` 结构

### 利益方
- 策略开发者：需要快速验证策略逻辑和参数优化
- 系统维护者：需要清晰的模块边界和最小的侵入性

## Goals / Non-Goals

### Goals
- 提供基于历史数据的策略回测能力
- 支持 CSV 格式的 Tick/K线历史数据加载
- 实现简单但正确的模拟撮合（支持市价单和限价单）
- 输出核心绩效指标（总收益率、最大回撤、夏普比率、胜率）
- 保持策略代码在实盘/回测间零修改复用

### Non-Goals
- 不实现多资产/多策略并行回测（后续迭代）
- 不实现滑点模型和手续费模型的高级定制（初版使用固定参数）
- 不实现实时可视化和图表展示（初版仅终端文本输出）
- 不实现参数优化/网格搜索功能（后续迭代）
- 不支持除 CSV 以外的数据源格式（后续可扩展）

## Decisions

### Decision 1: BacktestGateway 继承 Gateway 基类

**选择**：`BacktestGateway` 继承 `market::base::Gateway`，作为一个"虚拟交易所网关"注入引擎。

**理由**：
- 现有 `Gateway` 基类已定义完整的行情推送和订单处理接口
- 策略通过 `Engine` 事件系统接收数据，不直接依赖 `Gateway` 实现
- 替换 Gateway 即可无感切换实盘/回测，策略代码零修改
- 符合项目已有的网关模式（Gateway Pattern）

**替代方案**：
- 独立回测引擎绕过 Engine：破坏架构一致性，策略需要适配两套接口
- 在 Engine 层添加回测模式分支：增加 Engine 复杂度，违反单一职责

### Decision 2: 数据回放驱动事件循环

**选择**：`BacktestGateway` 在 `run()` 中按时间顺序读取历史数据，逐条注入 Engine 事件通道。

**理由**：
- 复用现有 `Engine::on_event()` 事件分发机制
- 回放速度仅受 CPU 处理速度限制（无网络等待），天然高效
- 模拟时间通过数据中的 `timestamp_ms` 字段驱动，保证时序正确性

### Decision 3: 内置简单撮合引擎

**选择**：在 `backtest/match/` 下实现 `MatchEngine`，处理订单撮合。

**撮合规则**：
- **市价单**：以当前最新 Tick 价格立即成交
- **限价买单**：当 Tick 价格 ≤ 限价时成交
- **限价卖单**：当 Tick 价格 ≥ 限价时成交
- 初版不模拟部分成交，全量成交

**理由**：简单撮合模型足以验证策略逻辑正确性，复杂撮合模型（滑点、深度模拟）列为 Non-Goal。

### Decision 4: CSV 数据格式

**选择**：使用 CSV 作为历史数据输入格式。

**Tick 数据 CSV 格式**：
```
timestamp_ms,symbol,last_price,volume,open,high,low,close
```

**K线数据 CSV 格式**：
```
timestamp_ms,symbol,open,high,low,close,volume
```

**理由**：
- CSV 是最通用的数据交换格式，易于从各交易所 API 或第三方数据源获取
- 解析简单，无需引入额外依赖
- 后续可通过新增 DataLoader 子类扩展其他格式

### Decision 5: 绩效分析独立模块

**选择**：在 `backtest/base/` 下实现 `PerformanceAnalyzer`，在回测结束后统一计算指标。

**核心指标**：
| 指标 | 计算方式 |
|------|---------|
| 总收益率（Total Return） | (期末净值 - 初始资金) / 初始资金 |
| 最大回撤（Max Drawdown） | 净值曲线峰值到谷值的最大跌幅 |
| 夏普比率（Sharpe Ratio） | (年化收益率 - 无风险利率) / 年化波动率 |
| 胜率（Win Rate） | 盈利交易数 / 总交易数 |
| 盈亏比（Profit Factor） | 总盈利 / 总亏损 |

## Risks / Trade-offs

- **简单撮合不够真实** → 初版定位为策略逻辑验证，非精确盈亏预测。文档明确说明局限性。后续迭代可增加滑点/手续费模型。
- **CSV 数据量大时性能问题** → 使用流式读取（逐行读取），避免一次性加载全部数据到内存。对于 GB 级数据，后续可引入二进制格式（如 Parquet）。
- **单线程回放速度** → 回测无网络 I/O 等待，纯 CPU 计算，单线程即可达到可接受速度。如需优化可后续引入批量事件注入。
- **时间管理** → 回测中系统时间应使用数据时间戳而非真实时间。需要在 BacktestGateway 中维护模拟时钟。

## Migration Plan

无需迁移。此为纯新增功能，不修改任何现有接口或行为。
